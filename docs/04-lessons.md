# 04. 이번 스터디에서 배운 것

분석 결과보다 **분석 과정에서 틀렸던 것들**이 더 배울 게 많았습니다.
한 달 동안 걸려 넘어진 순서대로 적습니다.

---

## 1. 가장 위험한 건 "그럴듯한 숫자"였다

첫 주에 만든 보고서에 이런 문장이 있었습니다.

> "SW/AI 구인배율은 **0.70** (구인 16,770건 / 구직 24,000명)"
> "LLM/RAG/Agent 언급 비율이 **67% 이상**"

둘 다 **수집한 적 없는 숫자**였습니다.

수집 스크립트를 열어보니 API 호출 코드 아래에 이런 게 있었습니다.

```python
# 워크넷 - 직종별 구인/구직 정형 데이터 샘플
worknet_sample = [
    {"직종명": "소프트웨어 개발자 및 AI 엔지니어",
     "월별구인건수": 12450, "월별구직건수": 18900,
     "구인배율(구인/구직)": 0.65},
]
```

API가 실패해도 이 리터럴이 CSV로 저장됐습니다. 게다가 **파일에 저장된 값(0.65)과 보고서에 적힌 값(0.70)이 달랐습니다.** 분석 스크립트가 계산 결과와 무관하게 결론 문자열을 그대로 출력하고 있었기 때문입니다.

```python
insight = """
- 구인배율은 0.70으로 ...
- 'LLM', 'RAG' 우대 공고 비중이 67% 이상을 차지함.
"""
print(insight)   # 계산값은 위에서 구해놓고 쓰지 않음
```

**배운 것**: 숫자가 그럴듯할수록 출처를 확인해야 합니다. 특히 **자기가 쓴 코드일수록** 그렇습니다.

### 그래서 만든 규칙

1. 결론 문자열에 숫자를 하드코딩하지 않는다. 전부 계산값으로 만든다.
2. **인증키가 없거나 API가 실패하면 즉시 중단한다.** 대체값을 만들지 않는다.
3. 원본 응답을 `data/raw/`에 그대로 보존하고, 수집 이력(엔드포인트·파라미터·시각·건수)을 남긴다.

```python
def require_env(name: str, how_to_get: str) -> str:
    """키가 없을 때 대체 수치를 지어내지 않는 것이 이 함수의 존재 이유다."""
    value = os.environ.get(name, "").strip()
    if not value:
        raise SystemExit(f"[중단] {name} 키를 찾을 수 없습니다. 발급: {how_to_get}")
    return value
```

## 2. API는 틀린 요청에 오류를 주지 않는다

이번 스터디에서 가장 오래 헤맨 지점이자, 가장 크게 배운 부분입니다.

### 사례 A — 필터가 통째로 무시됐다

채용 공고를 두 직군으로 나눠 수집했는데, 두 집합의 job_id가 **99/100 동일**했습니다.

필터 파라미터를 서버가 **조용히 무시**하고 있었습니다. HTTP 200에 정상 JSON이 왔고, 다만 필터가 적용되지 않은 전체 목록이었을 뿐입니다. 오류가 없으니 알아챌 방법이 없었습니다.

> 즉 그때까지의 "AI 직무 vs 일반 직무 비교"는 **같은 데이터를 두 번 센 것**이었습니다.

### 사례 B — snake_case를 보냈더니 0건

국민연금 API가 계속 `totalCount=0`을 반환했습니다. `resultCode`는 `00 NORMAL_CODE`였습니다.
승인 대기라고 판단하고 하루를 기다렸습니다.

원인은 **파라미터 표기법**이었습니다.

| 요청 | 결과 |
| :--- | :--- |
| `wkpl_nm=대신정보통신` (snake_case) | `resultCode 00` / **totalCount=0** |
| `wkplNm=대신정보통신` (camelCase) | `resultCode 00` / **totalCount=26** |

서버가 모르는 파라미터를 오류로 돌려주지 않고 무시하기 때문에, **오타든 잘못된 표기든 전부 "정상 응답 + 0건"** 으로 보입니다.

**배운 것**: `200 OK`와 `resultCode: 00`은 **요청이 의도대로 해석됐다는 뜻이 아닙니다.**
결과가 0건이면 "데이터가 없다"가 아니라 **"내 요청이 무시됐을 수 있다"** 를 먼저 의심해야 합니다.

### 검증 방법

필터를 넣은 결과와 안 넣은 결과가 **다른지** 확인하면 됩니다. 한 줄이면 됩니다.

```python
base = ids({})                      # 필터 없음
filtered = ids({"category": 873})   # 필터 있음
assert set(base) != set(filtered), "필터가 무시되고 있음"
```

## 3. 데이터가 있다고 해서 내가 원하는 데이터는 아니다

KOSIS에서 통계표를 받아 162행을 수집했습니다. 성공했다고 생각했습니다.

내용을 열어보니 **"성별 경제활동인구 총괄 / 15세이상인구"** — 성별·농가별 인구수였습니다.
**산업 구분 자체가 없는 표**였습니다.

올바른 표(`DT_1DA9003S`)로 바꾸니 정보통신업이 분리된 78개월 시계열이 나왔습니다.

**배운 것**: 수집 성공 로그를 믿지 말고 **컬럼과 값을 눈으로 확인**해야 합니다.
`shape`, `unique()`, `isna().sum()` 세 줄이면 대부분 걸러집니다.

## 4. 100% 성공은 의심 신호다

기업명 매칭에서 268개 중 **20/20 = 100%** 매칭이 나왔습니다. 기뻐하기 전에 결과를 열어봤습니다.

| 입력 | 매칭 결과 | 업종 |
| :--- | :--- | :--- |
| 글로벌 IT 기업 | **상호가 겹치는 건설사** | 유리 및 창호 공사업 |
| 식품 브랜드 | **같은 상호의 음식점 지점** | 일식 음식점업 |

검색 API가 부분 문자열로 매칭하는데, 후보 중 첫 번째를 집는 폴백이 있었습니다.

완전 일치만 채택하도록 바꾸니 매칭률이 **88.4%로 떨어졌습니다.** 그게 맞는 숫자였습니다.

**배운 것**: 매칭률·정확도가 예상보다 좋으면 **먼저 틀린 케이스를 찾아봐야** 합니다.
그리고 **놓치는 것보다 틀리게 붙이는 것이 훨씬 나쁩니다.**

## 5. 표본 오염은 이상한 0%에서 드러난다

연차별 분석에서 `경력무관` 구간의 AI 스택 언급률이 **정확히 0.0%**, 전통 스택도 **0.0%** 였습니다.
두 지표가 동시에 0이 나오는 건 부자연스러웠습니다.

파보니 14건 전부 한 회사의 **`AI Tutor - {언어}` 다국어 공고**였습니다.
개발 직군이 아니라 언어 데이터 라벨링이었고, 동일 템플릿으로 14건이 올라와 있었습니다.

추가로 확인하니 **동일 본문 중복이 19개 그룹 41건**이었습니다.

408건 중 **35건(8.6%)** 이 중복이거나 비개발 공고였습니다. 제거 후 373건으로 다시 분석했습니다.

**배운 것**: **깔끔한 0%나 100%는 버그이거나 오염**입니다. 정상 데이터는 지저분합니다.

## 6. 부분 수집분은 저장하지 않는 게 낫다

구인배율을 구하려고 고용행정통계 API를 순회 수집했습니다. 550회 중 **91회 성공 후 전량 차단**됐습니다.

```
<error>HITS_EXCEEDED : 해당 사용자의 IP에서 조회할 수 있는 OPEN API 조회 횟수가 초과됐습니다</error>
```

문제는 그때까지 모인 데이터였습니다. 25개 구 중 **5개만**, 그것도 불균등하게 들어와 있었습니다.
이걸 저장했다면 나중에 "서울 데이터"로 착각했을 겁니다.

그래서 수집기에 이 분기를 넣었습니다.

```python
if quota_hit:
    # 부분 수집분은 지역/연령 커버리지가 들쭉날쭉해 통계로 쓸 수 없다.
    # 편향된 데이터를 파일로 남기지 않는 것이 이 분기의 목적이다.
    raise SystemExit("[중단] IP 단위 조회 한도 초과. 부분 수집분은 저장하지 않습니다.")
```

**배운 것**: **없는 데이터가 편향된 데이터보다 안전합니다.**

## 7. 못 구한 데이터를 인정하는 것도 결과다

이번 스터디의 원래 목표 중 하나는 **"개발자 구인배율"** 이었습니다. 결국 못 구했습니다.

* 워크넷 채용정보 API — **기업회원 전용**. 개인 계정은 호출 시점에 차단됩니다.
* EIS 고용행정통계 — 인증키는 불필요하지만 **IP 일일 쿼터(~100회)**. 시계열 수집 불가.
* 게다가 EIS가 뚫려도 직종이 **대분류 10개**까지만이라, SW 개발자는 `연구직 및 공학 기술직`에 기계·화학·전기와 함께 묶여 나옵니다.

**두 경로 모두 막혔고, 뚫려도 원하는 입도가 아니었습니다.**

억지로 대체 지표를 만들지 않고 **"산출 불가"로 기록**했습니다. 대신 다른 데이터(JD 연차 필드)로
같은 질문에 답했습니다 — 그게 신입 공고 12.9%입니다.

**배운 것**: 계획한 지표를 못 구했을 때 **비슷한 걸 억지로 끼워 맞추는 게 가장 위험**합니다.
못 구했다고 적고, 답할 수 있는 질문으로 바꾸는 편이 낫습니다.

## 8. 숫자가 상반될 때가 제일 재밌다

한국과 해외 데이터가 정반대로 보였습니다.

| | 한국 (KOSIS) | 글로벌 (HN) |
| :--- | :--- | :--- |
| 물량 | 2026-06 **역대 고점** | 2021 대비 **-77%** |

처음엔 둘 중 하나가 틀렸다고 생각했습니다. 아니었습니다. **서로 다른 것을 재고 있었습니다.**

* KOSIS = 산업의 **고용 스톡**(재직자 수)
* HN = 신규 **채용 플로우**(열린 문의 개수)

**재직자는 늘어도 신규 진입문은 좁아질 수 있습니다.** 이 구조가 국내에서 확인한
신입 공고 12.9%와 정확히 같은 방향을 가리켰습니다.

**배운 것**: 두 데이터가 충돌하면 **"무엇을 재고 있는가"** 를 먼저 확인해야 합니다.
모순처럼 보이는 지점이 대개 가장 흥미로운 발견입니다.
