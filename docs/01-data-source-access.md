## ❌ 막힘 — 고용24(work24) OPEN-API 전체

* **엔드포인트**: `https://www.work24.go.kr/cm/openApi/call/wk/callOpenApiSvcInfo210L01.do`
* **응답**: `<GO24><error>개인회원은 사용할 수 없는 OPEN-API입니다.</error></GO24>`
* **공식 안내**: "OPEN-API는 **고용24 기업회원 전용 서비스**입니다" (고객센터 > OPEN-API 소개)
* **인증키는 발급됩니다.** 신청 단계에서 막지 않고 **호출 시점에 차단**하기 때문에, 신청할 때는 제한 안내가 보이지 않습니다.
* **공공데이터포털 우회도 안 됩니다 (2026-08-11 재확인).** [워크넷 채용정보 데이터셋(3038225)](https://www.data.go.kr/data/3038225/openapi.do)은 포털이 호스팅하지 않는 **LINK 타입**이라, 호출도 인증키도 결국 work24로 돌아갑니다. 같은 키로 레거시 `openapi.work.go.kr/opi/opi/opia/wantedApi.do` 도 호출해봤으나 `유효하지 않은 인증키 입니다`(`messageCd 002`) — 경로는 살아있지만 work24 키를 인식하지 않습니다.

## ✅ 열림 — EIS 고용행정통계 API (**인증키 불필요**)

work24와 **별개 계열**이며, 인증키 없이 누구나 호출됩니다.

| API | 엔드포인트 | 제공 지표 |
| :--- | :--- | :--- |
| 구인·구직 현황 (OPIA) | `https://eis.work24.go.kr/opi/joApi.do` | 신규구인인원수, 신규구직건수, 취업건수, 유효구인인원 |
| 피보험자 (OPIB) | `https://eis.work24.go.kr/opi/ipsApi.do` | 순수 피보험자수, 취득·상실자수 |
| 실업급여 (OPIC) | `https://eis.work24.go.kr/opi/uepsApi.do` | 수급자격신청자수, 지급자수·건수·액 |

### 요청 예시 (실제 200 응답 확인)

```
https://eis.work24.go.kr/opi/joApi.do
  ?apiSecd=OPIA&rsdAreaCd=11110&sxdsCd=M&ageCd=01
  &rernSecd=XML&closStdrYm=202512&bgnPage=1&display=100
```

* 응답 인코딩은 **EUC-KR** (UTF-8 아님, 파싱 시 주의)
* `display`는 **10 초과 10000 미만**이어야 함 (10 이하는 오류)

### 🎯 구인배율 산출 가능

`newJoNmpr`(신규구인인원수) / `newJhntNmpr`(신규구직건수) 로 **직접 계산 가능**합니다.
1차 보고서 초판의 "구인배율 0.70"은 근거 없는 값이었지만, 이 API로는 **실측 대체가 가능**합니다.

### ⚠️ 두 가지 제약

**0. IP 단위 일일 조회 한도 — 이게 결정타입니다 (2026-08-10 실측)**

서울 25개구 × 2성별 × 11연령 = 550회를 실제로 돌린 결과, **91회 성공 후 전량 차단**됐습니다.

```
<error>HITS_EXCEEDED : 해당 사용자의 IP에서 조회할 수 있는 OPEN API 조회 횟수가 초과됐습니다</error>
```

* 60초 대기 후 재시도해도 계속 차단 → 분당 스로틀이 아니라 **일일 IP 쿼터**로 판단
* 실측 성공 횟수는 약 90~100회 수준
* 서울 1개월치(550회)를 받으려면 **약 6일**, 12개월치는 **약 66일** 필요

➔ **대량 순회 수집은 사실상 불가능합니다.** 부분 수집분은 25개 구 중 5개만, 그것도 불균등하게 들어와 통계로 쓸 수 없어 폐기했습니다.

**1. 집계 코드가 없어 호출량이 큼**

`rsdAreaCd`(시·군·구) + `sxdsCd`(성별) + `ageCd`(5세 연령) 이 **전부 필수**이고, "전체" 값이 없습니다.

| 시도한 값 | 결과 |
| :--- | :--- |
| `sxdsCd=A` / `T` / `00` | `성별 구분코드가 유효하지 않습니다` |
| `sxdsCd=Z` (무관) | 0건 |
| `ageCd=00` / `99` | 0건 |
| `rsdAreaCd=11` (시도 2자리) | 0건 (5자리 시군구 필수) |

➔ 전국 1개월치 = 약 250개 시군구 × 2성별 × 11연령 ≈ **5,500회 호출**

**2. 직종이 대분류 10개까지만 제공됨**

```
000000 경영·사무·금융·보험직        500000 미용·여행·숙박·음식·경비·청소직
100000 연구직 및 공학 기술직        600000 영업·판매·운전·운송직
200000 교육·법률·사회복지·경찰·소방직  700000 건설·채굴직
300000 보건·의료직                 800000 설치·정비·생산직
400000 예술·디자인·방송·스포츠직     900000 농림어업직
```

➔ SW 개발자는 `100000 연구직 및 공학 기술직`에 묶여 있고, **개발 직군만 분리할 수 없습니다.**
   전 공학 분야(기계·화학·전기 등)가 함께 집계됩니다.

### 🐞 국민연금 API 함정 — 파라미터가 camelCase다

가장 오래 막혔던 지점입니다. 승인이 났는데도 계속 `totalCount=0`이 나왔습니다.

| 요청 | 결과 |
| :--- | :--- |
| `wkpl_nm=대신정보통신` (snake_case) | `resultCode 00` / **totalCount=0** |
| `wkplNm=대신정보통신` (camelCase) | `resultCode 00` / **totalCount=26** |
| `ldongAddrMgplDgCd=11&ldongAddrMgplSgguCd=545` | **totalCount=105,120** |

**서버가 모르는 파라미터를 오류로 돌려주지 않고 조용히 무시**하기 때문에, 오타든 잘못된 표기든
전부 "정상 응답 + 0건"으로 보입니다. 승인 대기 문제로 오인하기 쉽습니다.

* 검색 조건 없이 호출하면 0건입니다. **최소 1개 조건이 필요**합니다.
* 인증키는 **Decoding 값**을 써야 합니다 (Encoding 값은 이중 인코딩돼 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`).

### 국민연금 3개 오퍼레이션

| 오퍼레이션 | 입력 | 출력 |
| :--- | :--- | :--- |
| `getBassInfoSearchV2` | `wkplNm`, 지역코드 | 사업장명, 주소, **seq** |
| `getDetailInfoSearchV2` | `seq` | 업종명/코드, **총가입자수**, 당월고지금액 |
| `getPdAcctoSttusInfoSearchV2` | `seq`, `dataCrtYm` | **신규취득자수(입사)**, **상실자수(퇴사)** |

⚠️ 기간별 현황은 **당월 단일 스냅샷**(현재 202606)이며 과거 시계열이 아닙니다.

## 📌 결론

1. **워크넷 채용정보 원본은 개인 계정으로 접근 불가**입니다. 사업자등록번호 기반 기업회원 전환이 유일한 정공법입니다.
2. **EIS API는 인증키 없이 열려 있지만 실용성이 없습니다.** IP 일일 쿼터(~100회) 때문에 시계열 수집이 불가능하고, 직종도 대분류까지만 나옵니다.
3. **결론: "개발자 구인배율"은 개인 계정으로 도달 가능한 경로가 없습니다.** 이 지표는 포기하는 것이 맞습니다.
4. **대안은 국내 채용 플랫폼 JD의 `annual_from`/`annual_to` 필드**로 연차별 요구 스택 차이를 분석하는 것입니다 (이미 수집된 408건에 포함, 추가 수집 불필요).

### 기업명 매칭 주의

국내 채용 플랫폼는 **브랜드명**, 국민연금은 **법인등기명**을 씁니다. 검색 API가 부분 문자열로 매칭하기 때문에
후보 중 아무거나 고르면 오매칭이 납니다. 실제 사례:

* 글로벌 IT 기업 → **상호가 겹치는 건설사** (유리 및 창호 공사업) ❌
* 식품 브랜드 → **같은 상호의 음식점 지점** (일식 음식점업) ❌

➔ 수집기는 **정규화 후 완전 일치만 채택**하고, 나머지는 미매칭으로 남깁니다.
   매칭을 놓치는 편이 틀린 기업을 붙이는 것보다 낫습니다.
